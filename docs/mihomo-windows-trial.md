# Clash Verge / Mihomo в Windows

15 октября 2026 проверен Mihomo 1.19.32: встроенный MASQUE (WARP) и WireGuard
работают в одном процессе без usque, sing-box и Python UDP-реле в тракте данных.

## Текущее состояние — 15 октября 2026

- Clash Verge Rev 2.5.8: при вечерних замерах TUN включён, System Proxy выключен;
  mixed-порт 7897 продолжает принимать явно настроенные подключения.
- Auto Launch и Silent Start включены штатными настройками Clash.
- В группе VPN выбран My server, в Server transport — WARP.
- Google/YouTube и Discord идут DIRECT через zapret. Остальное следует правилам
  профиля, по умолчанию DIRECT. Эти сервисы не переводить в VPN ради исправления zapret.
- Для zapret general (EXP) требуется TCP timestamps **enabled**:
  `netsh interface tcp set global timestamps=enabled` от администратора.
- WireGuard-сервер wg-easy: MTU **1420**; клиент Mihomo: MTU 1280.
- Старые задачи v2rayN и DeviceSetup WARP WireGuard отключены, процессы остановлены.
  Файлы сохранены для отката; RealityFinder и zapret не удалены.
- Проверены HTTPS, UDP/HTTP3 и публичный запрос через QUIC Cloudflare Tunnel.
  Minecraft ответил внешнему серверу при TUN с временным допуском IP и пробросом.
  Временные изменения восстановлены; постоянного UPnP-проброса TCP/25565 сейчас нет.
- Proton **не добавлен**. [Как добавить его вручную](proton-clash.md).
- Ядру `verge-mihomo.exe` установлен AboveNormal: текущий процесс проверен,
  для следующих запусков сохранён IFEO `PerfOptions/CpuPriorityClass=6`.
  Это не устранило игровые задержки; прежняя настройка sing-box к новому имени не относилась.

Профиль использует peer 10.203.13.5 (старое имя native-mac): не запускать его
одновременно на Mac. Перед настройкой Mac создать ему отдельного peer.

## Профиль и управление

Генератор `mihomo/build_profile.py` принимает отдельно WARP account JSON,
обычный WireGuard `.conf` и политику `configs/v2rayn/windows/routes.json`.
Дополнительный `--proton <file.conf>` добавляет Proton в переключатель VPN.
Proton без пользовательского конфига не добавлен и не проверен.
JSON-результат является допустимым YAML для импорта в Clash Verge Rev.
Каталог результата нужно заранее защитить ACL: профиль содержит ключи.

```powershell
python mihomo/build_profile.py --warp-account C:\private\account.json `
  --wireguard C:\private\server.conf --output C:\private\device-setup.yaml
python -m unittest discover -s mihomo -p 'test_*.py'
```

Переключатель `VPN`: My server / WARP / Proton (если импортирован).
`Server transport`: WARP / DIRECT — способ подключения к своему серверу.
После смены транспорта перезагрузить ядро, чтобы пересоздать WireGuard-соединение;
старые соединения не обязаны менять маршрут при выборе другой группы.
VPN-группа не имеет автоматического отката на DIRECT.

Прямой доступ — правило по умолчанию. Порядок доменных, сетевых и процессных
исключений перенесён из существующего профиля. Для BitTorrent нет точного
аналога protocol matcher: добавлены прямые правила для qbittorrent.exe,
uTorrent.exe, Transmission-qt.exe; для других торрент-клиентов нужно добавить
своё правило процесса. Это отличие от исходного профиля, а не полная эквивалентность.

DNS: fake-ip и DoH; VPN-резолвер через выбранный VPN, direct/bootstrap — напрямую.
Собственный DoH приложений может обходить доменные правила клиента: это нужно
проверить при переходе системного TUN. IPv6 в тестовом профиле выключен;
полная проверка IPv6-маршрутизации ещё не проведена.
Привязка исходящих сокетов к Ethernet исключает захват транспорта старым TUN.
На другом устройстве указать актуальное имя через `--interface`.

### Сбой после перезагрузки 16 октября: отсутствует ru-blocked

Clash отказывался применять профиль: `country code ru-blocked not found in geoip.dat`.
В каталоге приложения оказались DAT-файлы той же длины и даты, что в ресурсах
установки Clash. В Clash Verge Rev 2.5.8 функция `init_resources` заменяет
стандартные Geo-файлы при более новой дате файла из установки. Поэтому замена
общих DAT вручную не обеспечивает устойчивость к последующим запускам/обновлениям.
Это отдельный сбой запуска, не результат экспериментов со стеком TUN.

Для первоначального восстановления использованы локальные базы v2rayN: профиль
прошёл проверку Mihomo. Затем обе ссылки на категорию ru-blocked заменены на
отдельные локальные RULE-SET с сохранением позиции, назначения VPN и no-resolve.
Пути: `rule-providers/device-setup/ru-blocked-ip.yaml` и `ru-blocked-domain.yaml`
в каталоге конфигурации Clash. Остальные правила, WARP и ключи не менялись.
Снимок содержит 88602 IP-правила и 37151 доменное правило. Файлы и manifest
с SHA256 хранятся локально, в Git не включены.

Экспорт: `mihomo/freeze_ru_rules.py --geodata <каталог-DAT> --output <каталог-Clash>/rule-providers/device-setup`.
Для нового профиля генератор `build_profile.py` принимает `--geodata-dir <каталог-DAT>`;
он создаёт профиль и каталог rule-providers рядом. При импорте в GUI этот каталог
нужно также скопировать в корень конфигурации Clash, затем перезагрузить профиль.
Списки являются фиксированным снимком: обновляются повторным явным экспортом
из доверенных DAT. Не заменять их случайными списками другого источника.

Проверка включает запуск отдельного ядра без TUN и VPN: API должен показать
не нулевые ruleCount, соответствующие manifest. Одного `mihomo -t` недостаточно:
он не подтверждает загрузку содержимого providers. YAML этих файлов должен
содержать один элемент на строку: JSON-представление массива давало пустые списки
в оптимизированном парсере providers. Три unit-теста проверяют перенос порядка
правил и no-resolve, IPv4/IPv6, доменные суффиксы/точные домены и отказ на
повреждённых или неподдерживаемых данных.

Во время восстановления Clash запускался с TUN выключенным, чтобы не включать
второй TUN поверх временно возвращённого v2rayN. Через прокси Clash прошли
OpenAI (401 без ключа), X (200), gstatic (204); тест задержки My server через WARP
показал 96 мс. Резервная копия: `%USERPROFILE%/.device-setup/mihomo-trial/recovery-20261016`.


После повторного запуска GUI 16 октября API рабочего ядра подтвердил загрузку
обоих локальных providers (37151/88602). Старый v2rayN остановлен пользователем,
TUN Clash включён. При проверке обнаружено, что восстановленный локальный
снимок ru-blocked не включает текущие адреса Telegram (149.154.167.51,
91.108.56.144). Telegram добавлен отдельными правилами процесса, доменов и
официальных CIDR https://core.telegram.org/resources/cidr.txt (проверены 16 октября).
Правила применены в работающем ядре, сохранены в приватном профиле и исходной
Windows-политике репозитория. API показал Telegram.exe через My server/VPN
с полученными данными; пользователь подтвердил, что Telegram заработал.
Синтетические MTProto-пробы этого запуска получили EOF; их нельзя записывать
как успешные. Итог подтверждён фактическими соединениями приложения и пользователем.
На момент подтверждения TUN и System Proxy Clash включены; игровые лаги этим
исправлением не устранялись.
