# Happ на iPhone: выборочный VPN

Готовая маршрутизация по мотивам профиля v2rayN «RUv1-Заблокированное»: заблокированные сайты, Google/YouTube и ChatGPT идут через VPN, остальной трафик — напрямую. Полные списки `ru-blocked` сохранены, блокировка рекламы отключена.

**Нужна своя рабочая подписка или ссылка на VPN-сервер.** Этот профиль определяет маршруты и DNS; доступа к серверу в нём нет. Можно пересылать эту страницу вместе с профилем.

## Быстрая настройка

1. Установите **Happ** по ссылке с [официального сайта](https://happ.info). Инструкция проверена в Happ 5.9.0 на iPhone.
2. Добавьте свою подписку или `vless://…` через **+ → Вставить из буфера обмена**. Если сервер уже есть в Happ, используйте его.
3. Откройте [готовую ссылку маршрутизации](https://raw.githubusercontent.com/jellybebra/device-setup/main/configs/happ/routing-link.txt) и скопируйте **всё содержимое страницы**: одну строку, начинающуюся с `happ://routing/onadd/`. Копировать нужно саму строку, а не адрес страницы.
4. Вернитесь в Happ и выберите импорт из буфера обмена в меню **+**. Должен появиться профиль **v2rayN - iPhone**. Это профиль маршрутизации, поэтому нового VPN-сервера он не добавляет.
5. У нужной подписки на главном экране откройте **⋯ → Routing / Маршрутизация**. Если импортированный профиль находится только в разделе **SERVER-LIST**, выберите **⋯ → Copy from / Копировать из → v2rayN - iPhone**. Затем выберите кружок рядом с этим профилем в своей подписке и включите маршрутизацию.
6. В настройках Geo-файлов обновите **GeoSite** и **GeoIP**. Ссылки на базы уже включены в профиль. Дождитесь окончания обеих загрузок и включите **Truncate geo files / Обрезать Geo-файлы**, если этот переключатель доступен. В профиле также установлен `UseChunkFiles: "true"`.
7. Подключитесь к серверу; при первом подключении разрешите iOS добавить VPN-конфигурацию. После изменения маршрутизации отключите и снова включите VPN.
8. Выполните **Check current connection / Проверить текущее соединение**, затем откройте нужные сайты, например YouTube и ChatGPT. В YouTube проверьте не только запуск ролика, но и минуту воспроизведения с перемоткой. Если видео останавливается через несколько секунд, см. раздел ниже.

Названия пунктов зависят от языка и версии Happ. Важно выбрать профиль именно у используемой подписки: одного импорта в общий список недостаточно.

Если импорт из буфера не срабатывает, скопируйте [JSON профиля](https://raw.githubusercontent.com/jellybebra/device-setup/main/configs/happ/routing.json) в [официальный генератор маршрутизации Happ](https://routing.happ.su/ru), создайте ссылку или QR-код и импортируйте полученный профиль.

## Что настроено

| Трафик / параметр | Настройка |
| --- | --- |
| Заблокированные домены и IP | Через VPN: полные `geosite:ru-blocked` и `geoip:ru-blocked` из базы runetfreedom |
| Google и YouTube | Через VPN: `geosite:google` |
| ChatGPT | Через VPN: домены OpenAI, статические файлы, авторизация и вспомогательные сервисы; точный список в JSON |
| Локальная сеть | Напрямую: `geosite:private`, `geoip:private` |
| Остальные адреса | Напрямую: `GlobalProxy: "false"` |
| Блокировка рекламы | Отключена: списки блокировки пустые |
| DNS для проксируемых запросов | Google DoH: `https://dns.google/dns-query`, IP `8.8.8.8` |
| Прямой DNS | `77.88.8.8` по UDP |
| Публичные DNS IP | `1.0.0.1`, `1.1.1.1`, `8.8.8.8`, `8.8.4.4` направлены через VPN |
| Стратегия доменов | `IPOnDemand` |
| Fake DNS | Выключен |

Профиль меняет маршрутизацию и DNS. Параметры сервера, TLS/Reality и ключи берутся из вашей подписки. Индивидуальное IP-исключение исходного устройства в общий профиль не включено.

## YouTube загружает только первые несколько секунд

В Happ 5.9.0 на iPhone 16 Pro Max новые ролики останавливались на 7–10-й секунде при подключённом VPN. В журнале для запросов к `googlevideo.com` было видно направление через `proxy`, затем ошибку **`XTLS rejected UDP/443 traffic`**. По сообщению владельца, через тот же сервер в v2RayTun и на Mac видео работало.

После смены **Flow** в профиле VLESS два ранее не открывавшихся в этой проверке ролика воспроизводились без прежней остановки: один дошёл до 1:48, второй — до 2:41, оба с перемоткой на 70 секунд вперёд. Проверка выполнена на одном устройстве.

Чтобы применить изменение:

1. На главном экране Happ нажмите стрелку справа от используемого сервера.
2. В **Flow** замените **XTLS-RPRX-Vision** на **XTLS-RPRX-Vision-UDP443** (`xtls-rprx-vision-udp443`). Остальные параметры сервера оставьте прежними.
3. Нажмите **Done**, отключите и снова включите VPN.
4. Откройте несколько новых роликов, которые ещё не воспроизводились на устройстве, и проверьте загрузку после перемотки.

По [документации Xray](https://xtls.github.io/en/config/outbounds/vless.html#outboundconfigurationobject), обычный Vision отклоняет UDP/443, принуждая приложения перейти с QUIC на HTTPS. Вариант `vision-udp443` разрешает этот трафик. Это настройка сервера в клиенте: импорт `routing.json` или `routing-link.txt` её не меняет. Она применима к профилям с Vision; для других протоколов этот пункт не подходит.

При обновлении подписки ручная правка сервера может быть перезаписана. Если проблема вернулась после обновления, проверьте **Flow**; для постоянного применения параметр должен присутствовать в выдаваемой подпиской ссылке.

Предыдущая рекомендация включить **Xray TUN** и перезапустить YouTube сама по себе не устранила сбой: новые ролики продолжали зависать. Успешное воспроизведение ранее открытых видео было недостаточной проверкой. Во время проверки изменения Flow **Xray TUN** оставался включённым с **MTU 1500**, **Global Proxy** — выключенным, полные списки `ru-blocked` и профиль маршрутизации сохранены.

## Память iOS и отличия от v2rayN

В проверенной конфигурации подключение с полными списками и `category-ads-all` завершалось ошибкой **Tunnel memory limit exceeded (50MB)**. После удаления списка рекламы и включения обрезки Geo-файлов туннель подключился, встроенная проверка соединения прошла. Здесь опубликован вариант без рекламы; списки `ru-blocked` не заменены сокращёнными.

Обрезка Geo-файлов оставляет нужные профилю категории, а не сокращает сам список `ru-blocked`. Размер скачанного файла не равен расходу памяти туннеля. Базы обновляются, поэтому результат на другой версии приложения или с новыми базами может отличаться. При ошибке памяти сначала проверьте, что выбран именно этот профиль, обрезка включена и VPN переподключён.

Перенос не полностью повторяет v2rayN: отдельные правила по протоколу BitTorrent и диапазонам UDP-портов Discord не перенесены. Голосовые звонки и каждый сайт отдельно не проверялись; успешная встроенная проверка подтверждает соединение с сервером, но не работу всех сервисов.

## Файлы и источники

- [routing.json](../configs/happ/routing.json) — читаемый профиль, который можно изменить под себя.
- [routing-link.txt](../configs/happ/routing-link.txt) — тот же JSON, закодированный в Base64, для импорта в Happ. При правке JSON нужно заново создать ссылку, например через официальный генератор.
- [Документация Happ по маршрутизации](https://github.com/HappDev/happ_su/blob/main/dev-docs/routing.md) — формат профилей, импорт и привязка к подпискам.
- [Ссылки и параметры импорта Happ](https://github.com/HappDev/happ_su/blob/main/dev-docs/examples-of-links-and-parameters.md).
- [Базы runetfreedom/russia-v2ray-rules-dat](https://github.com/runetfreedom/russia-v2ray-rules-dat) — источник GeoSite и GeoIP. Базы загружаются из `releases/latest`; для получения новых списков обновляйте Geo-файлы в Happ.
