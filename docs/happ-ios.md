# Happ на iPhone

На устройстве есть два способа задать маршруты. Для обычной VLESS-подписки используется локальный профиль
**v2rayN - iPhone**. Маршруты должны быть выбраны у самой подписки. Профиль с таким же именем только в общем
списке ещё не означает, что он активен. [Правила](../configs/happ/routing.json) ·
[Профиль для импорта](../configs/happ/routing-link.txt)

У серверной подписки `/happ/` каждый вариант получает собственные правила внутри JSON. Отдельный импорт
локального профиля их не меняет. Этим объясняется, например, почему правило Brawl Stars по порту работает
для соответствующего варианта подписки и отсутствует в ссылке импорта.
[Генератор серверных профилей](https://github.com/jellybebra/vless-docker/blob/master/happ/happ_profile.py)

При остановке YouTube после первых секунд в этой установке помогало пустое поле Flow у клиента 3x-ui. Выбор
режима с прямым YouTube также меняет обработку QUIC. Это разные настройки.

## Passkey через QR

Для входа с iPhone в Chrome на компьютере нужны Bluetooth на обоих устройствах и прямой доступ к узлам
обмена ключами. Исключения ограничены этими узлами: остальной трафик Google продолжает следовать обычным
правилам.

Проверенный вариант сочетал выключенный **Xray TUN** в Happ, `routeOnly: true` и IPv4 для прямого выхода. С
включённым Xray TUN запрос уже шёл через `direct`, но повторное разрешение имени меняло IP и вход срывался.
Переключатель Xray TUN принадлежит приложению. Замена JSON подписки сама его не меняет. Проверка всей
цепочки — завершённый вход по свежему QR-коду.
[Требования к passkey между устройствами](https://learn.microsoft.com/en-us/entra/identity/authentication/how-to-register-passkey-authenticator?tabs=iOS)
