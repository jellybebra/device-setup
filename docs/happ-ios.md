# Happ на iOS

Для настройки YouTube в приложении выполните [эту инструкцию](happ-youtube-dpi.md).

Для входа по passkey через QR с включённым VPN выполните [инструкцию проверки](passkeys-vpn.md).

## Быстрая настройка

1. Добавьте свою подписку или `vless://…` через **+ → Вставить из буфера обмена**. Если сервер уже есть в Happ, используйте его.
2. Откройте [готовую ссылку маршрутизации](https://raw.githubusercontent.com/jellybebra/device-setup/main/configs/happ/routing-link.txt) и скопируйте **всё содержимое страницы**: одну строку, начинающуюся с `happ://routing/onadd/`. Копировать нужно саму строку, а не адрес страницы.
3. Вернитесь в Happ и выберите импорт из буфера обмена в меню **+**. Должен появиться профиль **v2rayN - iPhone**.
4. **У нужной подписки на главном экране** откройте **⋯ → Routing / Маршрутизация**. Если импортированный профиль находится только в разделе **SERVER-LIST**, выберите **⋯ → Copy from / Копировать из → v2rayN - iPhone**. Затем выберите кружок рядом с этим профилем в своей подписке и включите маршрутизацию.
5. В настройках Geo-файлов обновите **GeoSite** и **GeoIP**. Ссылки на базы уже включены в профиль. Дождитесь окончания обеих загрузок и включите **Truncate geo files / Обрезать Geo-файлы**, если этот переключатель доступен. В профиле также установлен `UseChunkFiles: "true"`.

## Не работал Brawl Stars

Добавил правило `geosite:supercell` через VPN и В JSON-подписке
`/happ/` TCP/UDP на порт назначения `9339` также отправляется через VPN, даже
если соединение содержит только IP. Это правило находится внутри JSON-конфигурации сервера, а не в `routing-link.txt`.

## YouTube загружает только первые несколько секунд

Надо в 3x-ui зайти в клиента и выбрать Flow: None

## YouTube

1. В ссылке своей подписки замените `/sub/` на `/happ/`:

   ```text
   https://example.com/sub/TOKEN
   https://example.com/happ/TOKEN
   ```

2. Скопируйте полученную ссылку и в Happ выберите **+ → Вставить из буфера**.
3. Выберите **Заблокированное + YouTube без рекламы** и включите VPN. При первом подключении разрешите добавление VPN-конфигурации.

Для входа по passkey с iPhone через QR на компьютере выключите **Xray TUN** в настройках Happ и переподключите VPN. Проверенная конфигурация и порядок обновления описаны в [инструкции passkey](passkeys-vpn.md).

# Вход по passkey через QR с включённым VPN на iPhone и компьютере

Для входа с iPhone на компьютере включите Bluetooth на обоих устройствах.

## Проверенная настройка Happ

На этом Mac в Chrome вход в Google с ключом доступа на iPhone прошёл с VPN на обоих устройствах после выключения **Xray TUN** в настройках Happ. Использовалась тестовая подписка с исключениями ниже, `sniffing.routeOnly: true` и IPv4 для прямого выхода. Эти настройки JSON перенесены в генератор подписки `/happ/`.

Вход также проверен после возврата исходных правил и обоих шаблонов Xray в v2rayN на Mac. Менять настройки v2rayN для этого входа не требуется.

1. В настройках Happ найдите **Xray TUN** (в некоторых версиях — в **Dev Settings**) и выключите его.
2. Обновите подписку и переподключите VPN, как описано ниже.
3. Повторите вход по новому QR-коду.

Переключатель Xray TUN задаётся в приложении отдельно от JSON подписки. Обычная подписка `/happ/` сама его не выключает. В [документации Happ](https://www.happ.su/main/dev-docs/app-management) управление этим параметром через заголовки подписки требует ProviderID.

В журналах двух неудачных попыток Happ использовал нативный Xray TUN: relay шёл через `direct`, но исходный IP заменялся адресом из повторного DNS-запроса даже при `routeOnly: true` в SOCKS-входе подписки. После выключения Xray TUN вход прошёл. Проверена вся эта комбинация настроек; достаточность одного переключателя без остальных изменений отдельно не проверялась.

## Исключения маршрутизации

В профиле маршрутизации Happ и подписке `/happ/` добавлены точные исключения `direct`:

- `cable.auth.com`
- `cable.ua5v.com`
- `app-site-association.cdn-apple.com`
- `app-site-association.networking.apple`

Эти адреса указаны в [требованиях Microsoft к passkey на разных устройствах](https://learn.microsoft.com/en-us/entra/identity/authentication/how-to-register-passkey-authenticator?tabs=iOS): их нужно пропускать без перехвата и сетевого прокси. Исключения относятся только к перечисленным хостам; Google и сайт, на который выполняется вход, продолжают использовать свои обычные правила.

## Обновление iPhone

- **Подписка `/happ/`:** после обновления сервиса Happ на сервере обновите подписку в приложении. Обновление должно заменить и JSON-конфигурацию сервера, и профиль маршрутизации **iPhone - YouTube DPI**. Отдельный импорт маршрутизации не заменяет правила внутри JSON-конфигурации.
- **Обычная подписка:** повторно импортируйте [routing-link.txt](../configs/happ/routing-link.txt), затем выберите обновлённый профиль **v2rayN - iPhone** у своей подписки, как описано в [инструкции Happ](happ-ios.md).

Переподключите VPN после обновления. У подписки `/happ/` выберите сервер **iPhone - YouTube DPI**. Для проверенного режима оставьте **Xray TUN выключенным**.

## Проверка

Если снова появляется системная ошибка, запишите время попытки и проверьте логи маршрутизации: relay должен идти через `direct`. Затем проверьте Bluetooth и доступность relay из сети iPhone, включая DNS. Ответ HTTP 404 на корневой URL relay подтверждает только доступность HTTPS; он не проверяет WebSocket, Bluetooth или сам вход по passkey.
