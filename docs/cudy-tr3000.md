# Cudy TR3000

Конфигурация рассчитана на **Cudy TR3000 256MB v1** (`cudy,tr3000-256mb-v1`) с OpenWrt 25.12.6. У обычного
TR3000 другая разметка flash. Образ, разделы загрузчика и заводские данные должны соответствовать ревизии
платы.

## Что идёт напрямую

| Назначение | Маршрут |
| --- | --- |
| Большинство сайтов | Напрямую. Для YouTube, X, Instagram и Discord применяются профили zapret2. Голос Discord остаётся прямым. |
| Pinterest | Пины, короткие ссылки `pin.it` и картинки `i.pinimg.com` выходят по общему прямому маршруту. При проверке с компьютера в LAN соединения к адресам Pinterest были видны на WAN роутера. |
| Vercel | Для сайтов на общем IP `216.150.1.1` Cudy меняет адрес назначения на `216.150.16.1`. Соединение идёт напрямую, имя сайта сохраняется. |
| Cloudflare Tunnel | С ПК без собственного VPN соединения HTTP/2 и QUIC выходят с Cudy к Cloudflare на порт 7844. Сервер 3x-ui в этом пути не участвует. |
| Telegram, OpenAI, Anthropic, Notion | Через VLESS по правилам PassWall2. Для вложений, CDN и соединений без доменного имени важны отдельные правила. |
| Google AI Studio | Сайт, Gemini API и служебные домены Playground выходят через финский узел `quiet` по TCP и QUIC. Через этот же узел идёт `accounts.google.com`, в том числе при входе в другие сервисы Google. |

Общий маршрут PassWall2 — прямой. Пустое правило, назначенное на VPN, способно перехватить весь оставшийся
трафик. Правила Cloudflare охватывают опубликованные диапазоны сети. Сайты с собственными адресами могут
потребовать отдельного правила. Адрес самого узла исключён из проксирования. Метка пакетов, сгенерированных
zapret2, не даёт PassWall2 повторно перехватить их.
[Настройки PassWall2](../configs/cudy-tr3000/prepare-private.py) ·
[Профили zapret2](../configs/cudy-tr3000/make-zapret.py) ·
[Исключение по метке](../configs/cudy-tr3000/zapret-guard.sh) ·
[Правило для Vercel](../configs/cudy-tr3000/30-vercel-ingress.nft)

После настройки VPN на Cudy запустите на роутере `python3 ai-studio-vpn.py`.
Скрипт читает параметры узла `quiet` из локального `/etc/vpn-chain/chain.json`.
Для доменов этого правила DNS роутера выдаёт адреса FakeDNS из `198.18.0.0/16`.
Xray восстанавливает имя и отправляет соединение на финский узел. Это исключает
совпадение с общими IP Google, которые могли попасть в набор прямых маршрутов
`psw2_split_white`. Для этой схемы клиент должен использовать DNS роутера.
Повторите команду после смены параметров узла. Для проверки откройте новый чат
в AI Studio, выберите текущий аккаунт через меню профиля и дождитесь появления
модели и поля ввода после возврата в Playground.
[Скрипт настройки AI Studio](../configs/cudy-tr3000/ai-studio-vpn.py)

Доменные правила работают только там, где можно определить имя. Голос Discord и STUN требуют правила по
UDP-портам. Для CDN OpenAI успешный HTTPS-запрос по TCP ещё не подтверждает правильный маршрут HTTP/3.
Открытое QUIC-соединение может пережить смену настройки, поэтому проверяется новое соединение клиента.
[Проверка QUIC](../configs/cudy-tr3000/quic-probe.py) ·
[Проверка Cloudflare Tunnel из LAN](../configs/cudy-tr3000/check-cloudflare-tunnel.py)

В цепочке REALITY для CDN OpenAI внешний узел должен пропускать UDP/443. Для Vision здесь используется
`xtls-rprx-vision-udp443`: обычный flow приводил к ошибке `XTLS rejected UDP/443 traffic`, хотя TCP
продолжал работать.

## DNS

Устройства обычно запрашивают DNS у Cudy по локальной сети. Для обычных имён роутер сначала обращается к
Cloudflare по DoH. Если ответа нет, локальный DNS-селектор примерно через секунду повторяет UDP-запрос, и
его обрабатывает Google DoH. Следующий запрос вне кэша снова начинается с Cloudflare. Оба сервиса доступны
по фиксированным IP до запуска VPN. Корректный DNS-ответ с недоступным IP сам по себе не вызывает
переключения.

| Исключение | Причина |
| --- | --- |
| Домены Meta | DNS передаётся через VLESS, веб-трафик идёт напрямую. При прямом DNS Instagram мог получить недоступный адрес CDN. |
| Адреса Vercel | Для части ответов DNS-селектор подставляет доступные адреса того же пула. При смене пула подстановки требуют проверки с LAN. |
| Быстрые туннели Cloudflare | Имена `trycloudflare.com` идут через локальный селектор в обход отрицательного кэша Xray. Новое имя иногда появляется с задержкой. |
| Имя VPN-сервера | Разрешается через прямой DoH с резервом. Если оба сервиса недоступны при запуске zapret2, сохраняется последний известный список адресов узла. |

При паузе Cloudflare запросы с ПК к LAN-адресу Cudy прошли по UDP и TCP. Прямой TCP-запрос на внутренний
порт селектора `15355` в тех же условиях превысил четыре секунды.

## Ограничения установки

- Маршрутизация рассчитана на IPv4. Включение IPv6 для клиентов требует отдельных правил для PassWall2 и
  zapret2.
- PassWall2 и служба DNS через VLESS используют проверенный бинарник из `/opt/xray`. Установка пакетного
  Xray как зависимости PassWall2 сама по себе его не заменяет.
- Резервная копия настроек OpenWrt сохраняет локальные конфиги и файлы, перечисленные в
  `/etc/sysupgrade.conf`. Для чистой прошивки нужны также пакеты, в частности `https-dns-proxy`. Образ
  этой установки имеет SHA-256 `1c022e987da0c7662d639cc9ae3d728d94cdba2a63a46a054313eecc44fae33c`.
- Заводские разделы, данные подписки и ключи хранятся вне Git. Локальный комплект восстановления указан в
  `RECOVERY.txt` рядом с сохранёнными образами. Профиль VPN статический: при смене узла должны согласованно
  измениться настройки PassWall2, профиль DNS через VLESS, имя узла и исключения zapret2.
