# Huawei AX3: VLESS на роутере

## Что это

Набор скриптов для Huawei **WS7100-20 VER.A**: роутер сам направляет выбранные
соединения через VLESS, обрабатывает DNS и запускает всё после перезагрузки.
Правила действуют для подключённых к нему устройств по Ethernet и Wi-Fi.
Постоянно работающий компьютер и v2rayN на клиентах не нужны.

В комплекте — [скрипты и шаблон профиля](../configs/huawei-ax3/):

| Трафик | Маршрут в шаблоне |
| --- | --- |
| YouTube и видеосерверы googlevideo | Напрямую через tpws, который разделяет TLS-запросы для обхода DPI |
| X, служебные соединения Discord, перечисленные домены ChatGPT, Claude и Telegram | Через ваш VLESS-сервер |
| Игровой UDP, голос Discord и другой UDP, кроме исключений ниже | Напрямую через обычный NAT роутера, без HEV/Xray |
| UDP/53 к внешним DNS и UDP/7844 | Через HEV/Xray; direct или proxy определяется профилем |
| DNS к адресу Huawei | Через встроенный DNS-over-HTTPS Xray |
| Остальное | Напрямую; дополнительные правила добавляются в профиль |

TCP обрабатывает Xray. UDP по умолчанию не проходит через пользовательский
туннель: игры на разных серверах не требуют списка исключений по IP.
Через hev-socks5-tunnel в Xray попадают только порты из `UDP_TUNNEL_PORTS`
в скрипте; изначально это `53,7844`. В шаблоне UDP/7844 направлен через VLESS.
UDP/443 отклоняется, чтобы браузеры использовали TCP вместо QUIC.

## Как настроить

### 1. Проверьте совместимость и подготовьте роутер

Инструкция рассчитана на **WS7100-20 VER.A с debug-прошивкой 10.0.5.26**,
ядром Linux 4.4.197 и доступом root. Она не подходит автоматически для других
ревизий AX3. Это установка поверх прошивки Huawei, не OpenWrt.

Если у вас обычная прошивка без root, сначала потребуется установить подходящую
debug-прошивку. Сверьте модель на наклейке, сохраните настройки и подготовьте
штатный образ для восстановления. Прошивку и процедуру recovery выбирайте
по своей аппаратной ревизии в [теме Huawei AX3](https://4pda.to/forum/index.php?showtopic=989679).
Прошивальщик и образы в этот репозиторий не входят; команды ниже начинаются
**после получения root-доступа**. Не используйте образ от другой ревизии.

Для постепенного перехода подключите Huawei отдельным роутером:
интернет или LAN основного роутера → WAN Huawei, компьютер → LAN Huawei.
Сначала проверьте обычный интернет без прокси. Подсети WAN и LAN должны отличаться.
В таком подключении остальные устройства основного роутера не затрагиваются.

Адреса, под которые подготовлены файлы:

| Параметр | Значение |
| --- | --- |
| Huawei, основная LAN | `192.168.3.1/24`, мост `br0` |
| Huawei, гостевая LAN, если включена | `192.168.155.1/24`, мост `br1` |
| Компьютер для управления | `192.168.3.2` — закрепите адрес в DHCP |

Если адреса другие, до установки измените `ADMIN`, `LAN` и оба `dns_addr`
в [mvp-service.sh](../configs/huawei-ax3/mvp-service.sh), адрес SOCKS-входа
в профиле, адреса подключения в [router_console.py](../configs/huawei-ax3/router_console.py)
и команды ниже. `LAN=192.168.0.0/16` охватывает обе сети, но правила применяются
только к входящему трафику мостов `br+`.

Подключитесь Telnet-клиентом к `192.168.3.1:23`. В консоли debug-прошивки:

```text
shell
su
```

Дальнейшие блоки `sh` выполняются в этой root-консоли роутера.
Проверьте наличие `/dev/net/tun`, команд `iptables`, `ip`, `ftpget`
и доступной для записи папки `/data`. Debug-консоль не шифрует соединение
и в этой прошивке предоставляет root без пароля. Используйте доверенную LAN;
не открывайте порты 23 и 3333 со стороны WAN. Скрипт ограничит их доступом
с управляющего ПК, но только после своего запуска.

### 2. Соберите файлы на компьютере

Скачайте репозиторий и создайте отдельную папку `huawei-upload` **вне него**.
Положите туда следующие файлы:

| Файл в папке | Откуда взять |
| --- | --- |
| `xray` | [Xray 1.8.17, Linux ARMv5](https://github.com/XTLS/Xray-core/releases/download/v1.8.17/Xray-linux-arm32-v5.zip): файл `xray` из ZIP |
| `hev-socks5-tunnel` | [Hev 2.19.0, linux-arm32](https://github.com/heiher/hev-socks5-tunnel/releases/download/2.19.0/hev-socks5-tunnel-linux-arm32), переименовать без суффикса платформы |
| `tpws` | [Zapret v72.13](https://github.com/bol-van/zapret/releases/download/v72.13/zapret-v72.13.zip): `binaries/linux-arm/tpws` внутри архива |
| `ca-certificates.crt` | [Набор корневых сертификатов curl](https://curl.se/ca/cacert.pem), сохранить под этим именем |
| `mvp-service.sh`, `boot.sh`, `S99mvp`, `udp-tunnel.yml` | [Папка configs/huawei-ax3](../configs/huawei-ax3/) |
| `profile-1.json`, `profile-2.json` | Подготовить на следующем шаге |

Берите именно указанные ARM-сборки: варианты с аппаратным floating point
на этой платформе не подходят. Версия Xray зафиксирована из-за совместимости
со старым ядром; её нельзя без проверки заменить последним релизом.
Шаблон не использует `geoip.dat` и `geosite.dat`, поэтому они не нужны.
Shell-скрипты сохраняйте с переводами строк **LF**, без BOM.

### 3. Подставьте свой VLESS-профиль

Скопируйте [profile.example.json](../configs/huawei-ax3/profile.example.json)
в `huawei-upload/profile-1.json`. В объекте `outbounds` с `tag: "proxy"`
замените демонстрационные значения:

| Поле | Что подставить |
| --- | --- |
| `settings.vnext[0].address` и `port` | Адрес и порт вашего сервера |
| `settings.vnext[0].users[0].id` | Ваш UUID |
| `streamSettings.tlsSettings.serverName` | SNI из вашего профиля |
| `streamSettings` и, если нужен, `users[0].flow` | Транспорт, TLS/REALITY и flow, соответствующие серверу |

Пример рассчитан на VLESS TCP + TLS без Vision. Для REALITY, Vision или другого
транспорта удобнее экспортировать **Xray JSON** рабочего профиля из клиента
и заменить целиком только outbound VLESS, сохранив его тег `proxy`.
Входы, DNS и остальные outbounds оставьте из шаблона. Для REALITY Xray 1.8.17
использует `security: "reality"` и `realitySettings` с `serverName`, `fingerprint`,
`publicKey`, `shortId`; новые поля и транспорты из свежих клиентов могут быть
несовместимы с этой версией. Не отключайте проверку TLS-сертификата.

`profile-2.json` подготовьте таким же способом для второго сервера. Если сервер
один, скопируйте первый файл во второй. Скрипт выбирает готовые JSON-профили
с номерами 1 и 2; URL подписки он не импортирует и не обновляет.

Чтобы добавить сайт в прокси, допишите `domain:example.org` в список правила
с `outboundTag: "proxy"`. Оно охватывает домен и поддомены. Правила проверяются
сверху вниз; первое совпадение определяет маршрут. Если добавляете `geoip:`
или `geosite:`, отдельно установите соответствующие `.dat` со своими категориями.
Шаблон содержит базовый список доменов, а не полный набор правил вашего v2rayN.

### 4. Передайте файлы на Huawei

Один из способов — временный FTP-сервер на компьютере с Python 3.
В терминале компьютера, из папки, содержащей `huawei-upload`:

```powershell
python -m pip install pyftpdlib
python -m pyftpdlib -i 192.168.3.2 -p 2121 -r 60000-60009 -d ./huawei-upload -u mvp -P CHANGE_ME
```

Замените `CHANGE_ME` своим временным паролем, одинаковым в обеих командах
подключения. Убедитесь, что выбранные порты свободны, и разрешите входящие
TCP-подключения на 2121 и 60000–60009 только от `192.168.3.1` в брандмауэре ПК.
FTP передаёт файлы без шифрования: используйте его только в доверенной LAN
и остановите после копирования. [Параметры pyftpdlib](https://pyftpdlib.readthedocs.io/en/latest/cli.html).

На роутере, **при первой установке**:

```sh
mkdir -p /data/mvp
chmod 700 /data/mvp
for f in xray hev-socks5-tunnel tpws ca-certificates.crt mvp-service.sh boot.sh S99mvp udp-tunnel.yml profile-1.json profile-2.json; do
    ftpget -u mvp -p 'CHANGE_ME' -P 2121 192.168.3.2 "/data/mvp/$f" "$f" || break
done
ls -l /data/mvp
chmod 700 /data/mvp/xray /data/mvp/hev-socks5-tunnel /data/mvp/tpws /data/mvp/mvp-service.sh /data/mvp/boot.sh /data/mvp/S99mvp
chmod 600 /data/mvp/profile-1.json /data/mvp/profile-2.json
```

Если загрузка прервалась, сначала устраните ошибку и докопируйте файлы.
Сверьте размеры с файлами на ПК. Остановите FTP через Ctrl+C и удалите временные
правила брандмауэра. Сохраните свою папку с профилями в безопасном месте:
в ней находятся реквизиты доступа к прокси.

### 5. Проверьте конфигурацию и запустите вручную

Сначала проверьте синтаксис. При обновлении уже работающей установки выполните
`/bin/sh /data/mvp/mvp-service.sh off` **до проверки**: памяти мало, второй Xray
рядом с рабочим процессом может вызвать нехватку памяти.

```sh
export GOMEMLIMIT=40MiB GOGC=40 GOMAXPROCS=2
export XRAY_LOCATION_ASSET=/data/mvp
export SSL_CERT_FILE=/data/mvp/ca-certificates.crt
/bin/sh -n /data/mvp/mvp-service.sh
/data/mvp/xray run -test -config /data/mvp/profile-1.json
/data/mvp/xray run -test -config /data/mvp/profile-2.json
```

Оба профиля должны вывести `Configuration OK`. Проверка синтаксиса не проверяет
доступность сервера. При ошибке исправьте профиль до запуска.

```sh
/bin/sh /data/mvp/mvp-service.sh profile 1
```

Подождите около 30 секунд и проверьте:

```sh
/bin/sh /data/mvp/mvp-service.sh status
```

Ожидаются `Xray ready`, активные TCP-правила, `UDP native by default`
и `Local tpws running`.
На клиенте отключите TUN и системный прокси v2rayN, а также локальный Zapret,
чтобы проверять именно роутер. DNS клиента должен быть адресом Huawei.
Откройте X с изображениями, запустите видео YouTube и проверьте голос Discord
в обе стороны. При проблеме верните прямой интернет командой `off` из шага 7.

### 6. Включите автозапуск

Делайте это после успешной ручной проверки. Следующий способ относится только
к указанной debug-прошивке: Huawei подключает `/patch/etc` поверх `/etc`.
Проверьте `mount` и наличие `/patch`; не создавайте другой раздел вместо него.
Если `/patch/patch.ver` уже существует, прочитайте и сохраните его. Если его
содержимое отличается от строки ниже, не перезаписывайте существующий патч.

```sh
mount -o remount,rw /patch
mkdir -p /patch/etc/rc.d
cp /data/mvp/S99mvp /patch/etc/rc.d/S99mvp
chmod 755 /patch/etc/rc.d/S99mvp
echo 'WS7100-20-10.0.5.26_main_debug_patch26' > /patch/patch.ver
mount -o remount,ro /patch
```

Каждая команда должна завершиться без ошибки. Если `S99mvp` уже существовал,
сохраните его до замены. Перезагрузите Huawei из веб-панели и через 1–2 минуты
повторите `status` и проверки сайтов. Компьютер не должен запускать никаких
служб. Выбранный профиль и состояние «включено/выключено» сохраняются в `/data/mvp`.

### 7. Переключение профилей, диагностика и отключение

В root-консоли роутера:

```sh
/bin/sh /data/mvp/mvp-service.sh status
/bin/sh /data/mvp/mvp-service.sh profile 2
/bin/sh /data/mvp/mvp-service.sh off
/bin/sh /data/mvp/mvp-service.sh on
```

Это отдельные команды: статус, выбор второго профиля, прямой интернет,
повторное включение. Смена профиля прерывает текущие соединения и занимает
около 20–30 секунд. Автоматического переключения на другой сервер нет.

Необязательная панель на ПК: из корня репозитория запустите
`python configs/huawei-ax3/control.py` (нужен Python с Tkinter).
Она только отправляет команды; для работы интернета держать её открытой не нужно.

При ошибках смотрите `/tmp/mvp-watchdog.log`, `/tmp/mvp-xray.log`,
`/tmp/mvp-tun.log` и `/tmp/mvp-tpws.log` командой `cat`.
Если сайт отвечает, но картинки не загружаются, проверьте DNS клиента.
Если YouTube не работает напрямую у вашего провайдера, в его правиле профиля
поменяйте `outboundTag` с `dpi` на `proxy` и перезапустите выбранный профиль.
Если отдельному UDP-сервису нужен прокси, добавьте его порт в
`UDP_TUNNEL_PORTS` и IP/port-правило `proxy` в профиль Xray. Для звонков/WebRTC
с динамическими портами потребуется отдельный подбор правил; по имени процесса
на ПК роутер их не различает. Одного доменного правила Discord недостаточно.
При изменении списка портов выполните `off`, удалите отключённую собственную
цепочку командами `iptables -t mangle -F MVP_UDP` и
`iptables -t mangle -X MVP_UDP`, затем перезагрузите роутер, чтобы watchdog
прочитал новую версию скрипта, и выполните `on`. При переходе с прежней версии,
захватывавшей весь UDP, общий перехват снимается автоматически. Переподключите
уже открытые игровые соединения: старые записи NAT могут сохранять прежний путь.

Для обычного отключения достаточно `off`: собственный перехват снимается,
возвращаются прямой интернет и штатный DNS. Чтобы убрать и автозапуск:

```sh
/bin/sh /data/mvp/mvp-service.sh off
mount -o remount,rw /patch
mv /patch/etc/rc.d/S99mvp /patch/S99mvp.disabled
mount -o remount,ro /patch
```

Затем перезагрузите Huawei. До этого не удаляйте `/data/mvp`: запущенный
supervisor продолжает работать до перезагрузки. Отключение скриптов не возвращает
заводскую прошивку и не закрывает сам Telnet; для этого нужна отдельная процедура
возврата штатного образа. При потере связи подключите компьютер к основному
роутеру напрямую.

### Ограничения

- Обрабатывается IPv4. При доступном IPv6 он может идти в обход правил;
  для такой установки отключите выдачу IPv6 клиентам либо настройте его отдельно.
- tpws помогает не у каждого провайдера. Полного Zapret/nfqws здесь нет:
  в данном ядре отсутствует NFQUEUE. [Описание tpws](https://github.com/bol-van/zapret/blob/v72.13/docs/readme.md#tpws).
- Пока службы загружаются или восстанавливаются после сбоя, трафик идёт напрямую.
  Это не схема с запретом доступа при падении VPN.
- DNS использует DoH Cloudflare/Google; AAAA возвращается пустым из-за режима
  `UseIPv4`. DNS outbound Xray 1.8.17 отбрасывает запросы типа HTTPS (65).
- Скрипты привязаны к старой debug-прошивке и версиям компонентов выше.
  Обновления прошивки и бинарников требуют отдельной проверки совместимости.
