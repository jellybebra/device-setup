# Huawei AX3

Поддерживаемая конфигурация — **WS7100-20 VER.A**, debug-прошивка Huawei 10.0.5.26 и ядро Linux 4.4.197. Она
работает поверх штатной системы. Образы для других ревизий AX3 требуют отдельной проверки.

## Как разделён трафик

- Обычный игровой UDP остаётся в NAT роутера. Через пользовательский туннель идут только выбранные порты,
  включая внешний DNS, Cloudflare Tunnel и голос Discord. UDP/443 отклоняется, чтобы приложения переходили
  на TCP.
- Страницы и видео YouTube идут напрямую через tpws. API приложения, обложки и аватары имеют более
  приоритетные правила через VLESS. В этом ядре нет NFQUEUE, поэтому стратегии Cudy с nfqws2 сюда не
  переносятся.
- Cloudflare Tunnel идёт через VLESS. При сниффинге сохраняется IP, выбранный `cloudflared`.
  [Служба и перехват портов](../configs/huawei-ax3/mvp-service.sh) ·
  [Шаблон профиля](../configs/huawei-ax3/profile.example.json) ·
  [Клиентские исключения](v2rayn-routing.md#cloudflare-tunnel)

## Совместимость и границы

Процессору требуется ARMv5 soft-float, а в ядре отсутствует `eventfd`. Готовая сборка Xray 26.10.21 падала
при запуске. Совместимая сборка той же версии использует `pipe2`. Xray 1.8.17 не поддерживал нужный вариант
REALITY. Памяти мало для одновременного запуска двух экземпляров Xray.
[Сборка для AX3](../configs/huawei-ax3/build-xray-compatible.py) ·
[Проверка сетевых операций](../configs/huawei-ax3/netpoll-smoke.go)

Правила обрабатывают IPv4. IPv6 при наличии собственного маршрута может обойти их. Во время запуска и
восстановления служб соединения могут выйти напрямую и сохранить прежний маршрут даже после возвращения
прокси. Проверять выход следует на новом соединении.

Debug-консоль даёт root-доступ без пароля и шифрования. Ограничение адреса управляющего ПК действует только
после запуска сетевых правил. Консоль должна оставаться недоступной с WAN. Локальные профили содержат
реальные данные VLESS и хранятся отдельно от публичного шаблона.
