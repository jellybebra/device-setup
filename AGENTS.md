Весь этот чат — одна задача.

В начале новой задачи проверь актуальность кода, используя git, в каждой папке проекта, чтобы избежать работы над неактуальным кодом.

До изменения файлов проекта создай отдельный Git worktree и уникальную ветку задачи для каждого репозитория, который будешь изменять или использовать для запуска. Незакомиченные изменения переносить в worktree не нужно. Если удалённого репозитория нет — используй текущий локальный коммит.

При последующих сообщениях продолжай работу в тех же worktree — не создавай новые.

В опубликованных файлах используй домены example.com и документальные IP-адреса вместо адресов своих серверов. Реальные значения для запуска бери из локальной конфигурации.

### Порты

Используй отдельные свободные порты (проверь какие заняты) и локальные данные/БД под задачу. При наличии существующей локальной dev-БД используй её отдельную копию, а не пустую БД.

### Когда закончил

Запусти приложение локально, чтобы я мог проверить твою работу, но только если это разумно — если ты поправил тесты, например, то я их не увижу в интерфейсе и не проверю — запускать не надо.

Веб приложение: backend (если есть) и фронтенд (если есть).
Cоздай Cloudflare Tunnel, используя `cloudflared`. Для приложения с авторизацией используй `dev-<task>.vzl0m.com` и production OAuth Proxy; данные и сессии остаются локальными для задачи. Без авторизации используй временный Cloudflare URL.
Если есть backend, обязательно проверь связь с фронтендом - сделай чтобы всё работало.
Дай ссылки (localhost и cloudflare), я сам открою.

Десктопное приложение: у приложения может быть singleton токен, осторожно.

ТГ-бот: при конфликте использования токена останови запущенный тобой экземпляр.

Если это не GitHub-репозиторий и это какой-то проект, а не единоразовое действие, — предложи создать репозиторий (git, gh).

### Публикация и уборка

Когда я скажу заливать, нужно сделать commit, push, merge... короче чтобы в исходной ветке всё это было.

После успешной публикации нужно удали/заархивируй больше не нужные созданные worktree, удали слитые ветки и временные данные/БД и т.д. Если столкнешься с "blocked by policy", попробуй сузить операцию, убрав ненужные -Recurse/-Force.

iOS (только когда скажу заливать): собирай Release IPA для SideStore, сохраняя bundle ID и повышая номер сборки; передавай IPA на iPhone в «Файлы → SideStore» для установки поверх приложения без удаления. При установке/обновлении/продлении подписи через SideStore нужен LocalDevVPN. Xcode/`devicectl` используй для отладки; установка через них — по отдельной просьбе. Не проси подключить iPhone по проводу - проси разблокировать iPhone и подключить к той же Wi-Fi сети.

### Деплой

Когда я прошу задеплоить веб-приложение, то скорее всего это приложение на ssh test лежит в папке /opt/ где-то.
Учти, на test всего 30гб места, там иногда надо подчищать неиспользуемые всякие вещи от docker.

### Ubuntu Server

При настройке нового Ubuntu сервера, предложи:

1. Настроить вход по SSH за root по ключу без парольной фразы и SSH-алиас для подключения.
2. Включить или отключить автоматическую установку обновлений безопасности.
3. Включить Fail2Ban для SSH.
